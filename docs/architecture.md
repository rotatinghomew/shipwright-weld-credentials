# 跨厂实训与开工资格服务：设计说明

本服务把两类判断接在同一套事实之上：考评员核实的“实操是否达标”，与工位负责人在
开工时要确认的“这份资格今天能不能用于手头工单”。实现只依赖 Python 3.11 标准库，
代码位于 `app/`，测试位于 `tests/`。

## 1. 模块划分

| 模块 | 职责 |
| --- | --- |
| `app/timeutil.py` | 值班日 `HH:MM` 与分钟数互转、UTC+08:00 口径、半开区间时间语义 |
| `app/segments.py` | 时段交集、并集、扣除、并集分钟数（重叠不重复计时） |
| `app/models.py` | 报文事实（学员、政策、带教窗、签核、更正、名额、报名、成绩、工单）与运行期记录（认定结论、停工通知、审计事件） |
| `app/experience.py` | 实操经历认定：带教范围校验、跨厂归属冲突、无争议部分继续计入 |
| `app/seating.py` | 名额状态机：`hold` / `confirm` / `move`、确认期限、容量承诺 |
| `app/certification.py` | 资格条件汇总（经历分钟 + 工种考评）、状态与缺失条件 |
| `app/orders.py` | 开工门禁：工单类别、现场带教、资格状态 |
| `app/service.py` | 统一门面：事件受理、时点回放、查询裁剪、停工通知与审计轨迹 |
| `app/server.py` | 基于 `http.server` 的 JSON 接口与角色鉴权 |

## 2. 时间与回放模型

报文所有时间都是同一个值班日的 UTC+08:00 本地钟，内部统一换算为“当日零点起分钟数”。
时段一律含起点、不含终点。

所有认定（经历、名额、资格、门禁）都是**纯函数式推导**：给定某个时点，只使用
该时点之前已经到达的事实重新计算，不依赖可变结论缓存。因此任意历史时点都可以回放，
例如同一资格在 14:35 为 `active`、16:01 因两次撤正变为 `paused`。事件按
`signed_at` / `arrived_at` / `occurred` / `received` / `actual_start` 排序受理。

## 3. 业务规则落地位置

### 3.1 实操经历（`experience.py`）

一条签核可计入，必须同时满足：

1. 认定时点未被本厂更正撤回（`voided`）；
2. 带教师时间窗存在，且工厂、工种、班组与签核一致；
3. 学员组别在带教窗的限定组别内；
4. 签到时段与带教时间窗取交集，窗内部 分才计时。

跨厂处理：

- 同一学员同一工种、**不同分厂**的有效时段重叠 => 归属冲突，重叠段整体不计入，
  生成复核事项（`Dispute`）交实训中心，无争议部分继续计入；
- 同厂重叠按并集处理，天然不会算两遍；
- 冲突一方的签核后来被撤回 => 冲突自动解除（`conflict_cleared_by_void`），
  剩余时段恢复计入；
- 各厂只能撤正本厂签核，跨厂撤正返回 `factory_mismatch`，且不改变认定。

换厂带得走：认定按学员号聚合，不区分当前归属厂，`factory_minutes` 保留来源厂明细。

### 3.2 考评名额（`seating.py`）

- 报名（无论 hold/confirm）都先按**请求当时**的可计入分钟检查工种门槛，不达标拒收；
- `hold` 只是保留意向，不占用承诺容量；
- `confirm` 必须在 `confirm_by` 之前、`begins` 之前，且容量未满；
  容量只在承诺时兑现，因此一个名额不可能许给两个人（`seat_capacity_exhausted`）；
- `move` 只能放掉尚未开考的原报名；开考后撤考拒收（`exam_already_started`）；
- 保留在确认期限后失效（`sweep_expired`）。

### 3.3 成绩与资格（`certification.py`）

成绩必须携带能定位原申请的报名号，否则拒收。考评结论分四档：

- `passed`：实际签到、分数达通过线、名额仍属于该学员；
- `failed`：实际签到但分数不足——**已经知道不合格**；
- `pending_review`：无实际签到的分数、或迟到成绩与参加记录冲突——转人工复核，
  不能据此发证，也不能覆盖新考评；
- `awaiting_result`：名额已承诺但答复未到——**暂时不能确认**，与 `failed` 明确区分，
  等待期间名额不会再次分配。

迟到成绩（原报名已 move 或名额另许）仍可通过报名号回溯原报名，但标记 `late=true`，
不参与发证。

资格状态：

- `active`：经历分钟与工种考评两个条件都满足；
- `paused`：原本成立的依据被更正破坏（携带 `paused_by_corrections`），
  暂停依赖它的发证；`missing` 明确列出缺的是哪个条件、差多少分钟；
- `pending`：尚未攒够经历，或考评处于等待/待核/不合格。

考评开始后才发现资格依据有误：已参加的考评记录原样保留（成绩仍可查），
只是资格进入 `paused`，服务不会回删任何参加事实。

### 3.4 开工门禁（`orders.py` + `service.py`）

- 门禁只在**开工时点**（`actual_start`）做正式结论，排班 `planned_start` 再好看
  也不替代现场检查；未开工工单调用接口得到的是预览，不留正式结论；
- 政策的 `required_jobs` 决定资格可承担的工单类别；`seam` 可独立上岗，
  `pipe` 必须现场带教（`SUPERVISED_JOB_KINDS`）；
- 带教有效性 = 同班组 + 同工种 + 学员组别在带教范围 + 带教时间窗覆盖开工时刻；
- `paused` / `pending` 资格一律拦截，回执 `reasons` 给出全部拦截原因。

### 3.5 更正影响与停工通知（`service.py`）

撤正受理后重新认定资格，并判断是否还有其他有效依据：

- 仍有依据达标（含其他工种以外的同源依据）=> 不发通知；
- 不再够用且存在**已实际开工**的在制工单 => 生成 `StopNotice`，通知工位负责人
  停止继续安排受影响工作，消息中写明所缺条件，同时保留 `actual_start` 记录不回删；
- 未开工工单不发通知，由门禁自然拦截；
- 无关工种的资格与工单不受影响（按 `(worker, trade)` 隔离）。

### 3.6 可见性

- 学员只能查本人的经历、报名、证书（HTTP 层强制本人或实训中心）；
- 工位只拿到本工单的授权依据**索引**（签核号、报名号、成绩号、分钟汇总），
  看不到任何分厂的完整实训流水；
- 实训中心可看全部复核事项，以及每份资格的完整审计轨迹：开工时用了哪些事实、
  后来哪项更正改变了用工决定。

## 4. HTTP 接口

请求头 `X-Actor-Role` 与 `X-Actor-Id` 声明角色与业务身份。

| 方法 | 路径 | 角色 | 说明 |
| --- | --- | --- | --- |
| GET | `/api/health` | 任意 | 健康检查 |
| POST | `/api/intake/logs` | `factory` | 提交分段签到与带教签核（限本厂） |
| POST | `/api/intake/corrections` | `factory` | 撤正本厂签核（跨厂 403） |
| POST | `/api/intake/registrations` | `centre` | 实训中心提交报名/确认/撤考 |
| POST | `/api/intake/results` | `exam_point` | 考评点送成绩（限本考评点名额） |
| POST | `/api/intake/orders` | `station` | 工位登记工单（限本班组） |
| GET | `/api/workers/{id}/overview?as_of=HH:MM` | `worker` 本人 / `centre` | 学员视角总览 |
| GET | `/api/stations/orders/{id}?as_of=HH:MM` | `station`（本班组） | 工单门禁解释与授权索引 |
| GET | `/api/centre/disputes` | `centre` | 跨厂冲突复核列表 |
| POST | `/api/centre/disputes/{id}/resolve` | `centre` | 中心处置复核事项 |
| GET | `/api/centre/qualifications/{worker}/{trade}/trace` | `centre` | 资格审计轨迹 |

启动方式：

```sh
python3 -m app.server --data data/training_20261201.json --host 127.0.0.1 --port 8050
```
